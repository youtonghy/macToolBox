# 授权功耗采集

在「设置 → 通用 → 功耗采集」启用「授权功耗采集」，按系统提示允许 ToolBox 后台服务。授权完成后返回 ToolBox，打开有 CPU/GPU 功耗的菜单面板，等待约 2–3 秒。

关闭开关会先关闭采集模式，再注销辅助服务。拒绝授权不会显示伪造的 0 W；系统采集失败或读数超过 3 秒未更新时显示不可用。未授权模式继续使用 IOReport 和 SMC。

显示功耗期间，若读数连续约 30 秒不可用（等待系统授权除外），应用会自动重启辅助服务：服务缺失时在后台重新注册（不弹出授权窗口），并暂停重连约 17 秒，让旧辅助服务空闲退出，由 launchd 在下次连接时拉起新进程。仍不可用时继续重启，间隔依次加倍，最长 5 分钟；收到新读数、手动切换开关或重新打开功耗面板后恢复初始间隔。

连续 5 次重启后仍未收到新读数时，应用会自动关闭授权功耗采集（与手动关闭相同，会注销辅助服务），在开关下方显示「当前功能不可用」，并回退到 IOReport 和 SMC。失败次数跨功耗面板的打开与关闭累计，收到任一新读数即清零。手动重新开启后清除提示并重新计数。

## 为什么需要授权模式

在 M5 Max、macOS 27 build 26A5425a 的本机对照中，旧版采集代码单独运行仍为零；运行系统 powermetrics 后，旧代码的计数器才开始更新。代码相同、仅重新签名的 powermetrics 副本在 root 下也读到零，系统原版则读到正常 CPU 功耗。这强烈指向系统程序身份相关的差异，尚未确定具体内核检查。

授权模式直接运行 `/usr/bin/powermetrics --samplers cpu_power -f text -b 1 -i 1000 -n 5`，不依赖自定义辅助程序自行刷新受限计数器。CPU、GPU、ANE 和合计功耗来自同一份系统报告；不将 IOReport 的 DRAM/GPU SRAM 与这一来源混合。SMC 的整机功耗仍单独保留。

## 服务与权限

- `SMAppService` 管理 `com.youtonghy.toolbox.power-sampling`。描述文件位于应用包的 `Contents/Library/LaunchDaemons`，程序位于 `Contents/Library/LaunchServices`。
- 默认关闭。服务经系统管理员批准后才可启动，通过 Mach service 按需启动，没有常驻采集的 KeepAlive。
- 原生 NSXPC 签名要求校验调用者及服务端；签名要求从同一应用包的对应程序获取。开发版采用 ad-hoc 的具体代码哈希，正式签名采用指定签名要求。仅接受一个非 root 应用连接。
- 只暴露「获取采样」和「停止」两个方法。客户端不能提供命令、参数、环境变量或输出路径。系统进程只运行 CPU power sampler，不采集进程列表，不保存管理员密码。
- 断开连接或停止监控时结束子进程；客户端超过 6 秒不再请求时回收采集。辅助服务接受最新的合法连接（替换可能已失效的旧连接），没有连接约 15 秒后自行退出，由 launchd 在下一次连接时重新拉起，因此卡死的会话不会永远占据服务名。应用被替换后，仍在运行的旧辅助服务已无法通过客户端的签名校验（`errSecCSNoSuchCode`），而客户端每秒重连又会不断推迟空闲退出；因此辅助服务在接受连接前会检查自身可执行文件是否已被替换，若已替换则拒绝连接、停止采集并退出，由 launchd 拉起新版本。单批 5 个报告，避免辅助服务崩溃后留下无限运行的子进程；服务正常运行时另有 10 秒进程超时和终止兜底。注销服务时 launchd 回收进程组。

## 构建与更新

使用 `xcodegen generate` 后构建 ToolBox，辅助服务及描述文件会一起复制进应用包。`scripts/sign_nested_runtime.sh` 先签名辅助服务，再签名外层应用；辅助服务不携带应用的库验证例外权限。

授权后不要移动应用包。替换同一签名身份的新版本时，旧辅助服务会在新版应用首次连接时自动退出，无需手动关闭授权模式。没有 Team ID 的签名（本地证书或 ad-hoc）会让系统把服务的启动约束固定到辅助服务的代码哈希上，每次重新编译或更新后 launchd 都会拒绝启动它（`launchctl print system/com.youtonghy.toolbox.power-sampling` 显示 `EX_CONFIG` 与 `needs LWCR update`）。应用会记录注册时的辅助服务代码哈希，启动时（以及采集恢复时）发现不一致就先注销再重新注册服务；重新注册后系统可能要求再次在登录项中批准。正式发布需要验证当前发布证书与嵌套签名；不要用修改后的系统 powermetrics 副本替代系统路径。

本地证书的离线测试可设置 `TOOLBOX_SIGN_TIMESTAMP=none` 跳过嵌套组件签名的时间戳请求。正式分发仍使用默认的时间戳签名；本地测试构建不代表已完成公证。

## 验收

自动测试覆盖真实报告的分段读取、单位换算、缺失/无效值、过期读数、进程退出/取消/无请求回收，以及原生 XPC 对不匹配签名的拒绝。原有 IOReport 生命周期测试继续运行。

本机最终验收需手动完成系统授权：

1. 退出旧版，启动本次构建的 ToolBox，启用授权功耗采集并批准后台服务。
2. 打开功耗面板，确认 CPU 功耗更新。用系统 powermetrics 对照时，比较相邻采样趋势；两次独立采样的窗口不同，不要求逐值相等。
3. 关闭面板/退出应用，确认采集停止；重新打开后恢复。
4. 关闭授权开关，确认后台服务注销且原有采集方式恢复。重新启用时仍能正常工作。

若启用失败，设置页显示系统错误；可关闭开关移除服务后重新启用。辅助服务未注册或授权未完成时，应用不会把读数报告为正常零值。
